# Build Plan — Sandbox MMO-ARPG pivot

Companion to [`PIVOT_PLAN.md`](PIVOT_PLAN.md), which holds the design. This file is the
**execution order**: what to build, in what sequence, and how each phase proves itself.

**Sizing** is effort for one experienced engineer, because team size and calendar are still open:
**S** = days · **M** = 1–2 weeks · **L** = 3–6 weeks · **XL** = 2–3 months.
Art and audio are **not** included in the sizes; they're called out separately where they gate work.

**Branch:** `pivot/mmo`. `master` keeps the current playable co-op game until the experiment
earns the swap.

---

## Rules that hold for every phase

1. **Stay runnable.** Every phase ends in something you can launch and play. No phase may leave
   the build broken "until the next one lands."
2. **`sim/` and `world/` never import graphics.** Enforced by a headless build target in
   `test.sh`, from P0 onward. This is what makes a dedicated server possible at all.
3. **The server is the authority** on items, gold, skills and positions from P2 onward. The client
   only asks.
4. **The economy ledger (§5.9) logs from its first day.** Every gold or item faucet and sink,
   with a reason code. It can't be reconstructed later.
5. **Content is data, not code.** Items, recipes, nodes, skills, NPC demands, reserve policies all
   live in `data/` and hot-reload.
6. **Every phase adds its tests to `test.sh`.** The repo already has the habit
   (`combat_rules_test`, `game_logic_test`, `p2p/protocol_test`); keep it.

P0–P2 are infrastructure with no new gameplay: this is the expensive, unglamorous stretch.
**P3 is the first moment the pivot can be judged as a game.** Consider pulling its design
questions (keepsake rules, pacing) forward into playtests the moment the loop closes.

## P0 — Foundation (size **L**)

Done on the current raylib build. No visible change; everything here is a prerequisite that
gets harder later.

**Tasks**
- [~] **Package split** (`PIVOT_PLAN.md` §4.3) → `sim/` `world/` `net/` `backend/` `client/` `server/` `editor/`
  - [x] **Slice 1 — the core** is in `src/sim/`: `components.odin`, `ecs.odin` (`World`,
        `Simulation`, ECS wrappers), `players.odin`, `core_systems.odin` (`movement_system`,
        `self_destruct_system`). It imports only clockwork. `src/sim_aliases.odin` (generated by
        `tools/gen_sim_aliases.py`) re-exports these names into `main`, so no other file changed.
        Odin `::` aliases are the same entity, not a copy.
  - [ ] **Correction to the original plan:** "imports no raylib" does *not* mean "movable". Odin
        forbids cyclic imports, so a file can move into `sim` only if nothing it calls stays in
        `main`. `ai_system`, `damage_system`, `weapon_system`, `items` etc. call presentation
        directly: `play_sfx`, `camera_shake`, `push_dmg_number`, `push_explosion`, `ui_mark_dirty`.
        **Next slice:** add a `sim.Presentation` hooks struct (proc pointers, no-op by default;
        the client sets them at startup, the server leaves them empty). Then those systems can move.
  - [ ] Shrink `sim_aliases.odin` over time by qualifying call sites as `sim.Name`; delete it at zero.
- [x] **Headless build target.** `./build.sh server` → `bin/tormentas_server` (`src/server/`).
      `test.sh` now:
      - enforces import rules (`tools/check_boundaries.py`)
      - builds the server
      - **fails if the binary links any graphics/audio/UI/Steam symbol**, catching indirect
        dependencies too
      - runs it with invariant checks
      Debug binary is 775 KB vs the game's 6.8 MB, with 0 forbidden symbols vs the game's 4,925.
- [~] **Fix the destroy-path entity leak** — fixed in code, **awaiting playtest**. `world_tag_destroy`
      set `.ToDestroy` itself, so clockwork's `world_mark_destroy` early-returned and the id never
      reached `pending_destroy`. It was worse than a memory leak: `world_reset` goes through the same
      early return, so a leaked slot kept its component-pool bits across a level switch. Ids restart
      at 0, and the next entity created on that slot showed up in queries for components it never
      had, with the dead entity's data (`reset_leaves_no_ghost_components`). Fix:
      `world_tag_destroy` now calls `ecs.world_mark_destroy`; the separate `tagged` list and
      `world_reap_tagged` are gone. Tagged entities are freed by the end-of-tick sweep, so
      `world_is_valid` goes false for them one tick after tagging. The headless server now asserts
      the self-destruct entity is freed.
      An audit of every id held across frames found no unguarded reader. These visible changes are
      expected, and all are bug fixes:
      - **Carrion Crown** raises servants again after its first three die (dead servants used to
        hold their slots until the level reset).
      - **Corpses stop collecting status effects.** Burn/wet/oil rings no longer draw over killed
        enemies or exploded barrels.
      - **Editor "Capture overrides"** no longer saves a killed enemy's `Health.current = 0` into
        the level.
      **Playtest focus:** the three above, plus kills, projectiles, pickups and level switches.
- [ ] **Client-side destroy leak** (pre-existing, found in the same audit). A joined client runs
      only `sim_tick_predicted` (`netcode.odin:29`), which never calls `world_sweep`. Everything a
      client destroys, including the host's `ENTITY_SYNC_DESTROY`, keeps its slot, and the
      ghost-components-after-reset bug still applies there. Fix: sweep at the end of
      `sim_tick_predicted`. Ship it as its own change with a two-client playtest.
- [ ] **`build.ps1` server target + Windows symbol check.** `test.ps1` already runs the `sim` suite;
      the server build and the `dumpbin` equivalent of the `nm` check are macOS-only so far.
- [ ] **Spatial hash** replacing the all-pairs loop in `separation_system.odin:12`. Needed for
      scale, and a win for the current game too.
- [ ] **`ItemDef` / `ItemInstance` split** (§5.2). Today `SavedItem` inlines every base stat, the
      name, the icon and the description per item. Move definitions to `data/items/*.json`;
      instances keep id, def, qty, durability, quality, enchants.
- [ ] **Save migration** for the item change (`SAVE_VERSION` 7 → 8), or an explicit wipe. The
      roadmap already flags migration policy as undecided; decide it here.
- [ ] **Economy ledger skeleton** (§5.9): `EconomyEvent`, reason codes, an append-only sink. Wire
      the faucets and sinks that already exist (gold drops, shop buy/sell).
- [ ] **Snapshot fairness fix** in `netcode.odin:78`: sort by distance to each client before the
      256-entity cap, instead of query order. Today a monster next to you can be the one dropped.

**Exit:** the game plays exactly as it did; `./test.sh` builds a headless server package.
**Verify:** existing tests pass · a new import-boundary test · a save round-trip test across the
item migration.
**Risks:** the package split touches everything at once. Do it as one mechanical pass driven by
the compiler, in its own commit, with no behaviour changes mixed in.

## P1a — raylib → sokol, 2D parity (size **L**)

**Strategy: abstraction first, backend swap last.** There are 2,439 `rl.` uses in 47 files.
Swapping raylib out in one pass would leave the game unplayable for weeks (rule 1). Instead,
build our own `gfx` / `platform` / `cam` API **on top of raylib**, move every call site onto it
while the game keeps running, and only then reimplement that API on sokol.

**What the code adds to the original task list**
- **Lighting is the hidden cost.** `lighting.odin` (~1,000 lines, 258 `rl.` uses), 6 GLSL-330
  shaders in `data/shaders/`, and 82 `GetShaderLocation` calls. `fog_lights.fs` also draws the
  player's vision radius, which is gameplay (stealth), not decoration.
- **Interleaved passes.** `draw_playing` (`main.odin`) goes shadow RT → world RT → screen →
  sprite RT → screen. sokol can't nest passes or go back to the swapchain mid-frame, so the
  sokol backend draws into an offscreen **main target** and presents it once per frame.
- **Y-flip audit.** raylib render textures are drawn with a negative source height, and the
  shaders flip `gl_FragCoord` by hand. Metal and D3D put the origin top-left. Every RT draw and
  every `gl_FragCoord` use gets checked.
- **std140 uniforms.** `uniform vec2 u_light_pos[32]` pads each element to 16 bytes. Port
  uniform arrays as packed `vec4` arrays.
- **sokol_app gaps.** No window resize/position, monitor queries or mouse warp. The first two
  disappear with the window-mode decision. `SetMousePosition` is only used by the tools probe;
  replace it with synthetic mouse input in the platform layer.
- **Screenshots.** The tools probe uses `LoadImageFromScreen`. Confirm in the spike whether
  sokol_gfx can read pixels back; if not, add a small per-backend readback helper.
- **Free wins.** sokol keycodes use the GLFW values, like raylib's, so keybinds saved as `i32`
  in `config.odin` stay valid; mouse button numbers match too. The game uses no gamepad API,
  so sokol having none costs nothing.

**Step 1 results (2026-11-17, macOS/Metal run; Windows/D3D11 compiled but not run yet)**

`./build.sh spike` → `bin/tormentas_spike [--shot out.png] [--target main|world|sprite]`. It runs
the game's real pass order (world RT → main → sprite RT → main → present) and passes every check
in the frame it captures. Setup:
- `deps/sokol/`: sokol-odin `ae94aa5` (sokol `93aa187`), modules app/gfx/gl/glue/log/time/shape,
  manifest in `snapshot.json`. `tools/build-sokol.sh` builds the `.a` files on demand (gitignored).
- **sokol-shdc** is pinned by commit + SHA-256 in the same manifest and downloaded into
  `.local/sokol-shdc/` by `ensure_shdc` (`tools/common.sh`), only when a `.glsl` is newer than its
  committed `.glsl.odin`. Output targets `metal_macos:hlsl5`.

What it established:
1. **This sokol is view-based.** Textures and attachments are bound through `sg.make_view`, and
   resource updates go through staging buffers + `sg_copy_*` (no more dynamic/stream images).
   Write against the vendored examples, not older docs.
2. **sokol_gl silently drops alpha.** It turns a default write mask into RGB
   (`sokol_gl.h`, `_sgl_init_pipeline`), so offscreen targets came out fully transparent and every
   composite vanished. **Every sgl pipeline used offscreen needs `write_mask = .RGBA`.**
3. **No y-flips anywhere.** Render targets sample upright (orientation markers), and
   `gl_FragCoord` is top-left (a light placed at (140,140) lands top-left). The raylib shaders'
   `screen.y - gl_FragCoord.y` flips and the negative-height RT source rects both go away.
4. **One sgl layer per pass segment** handles the interleaved passes: record in game order with
   `sgl.layer(n)`, replay with `sgl.context_draw_layer` inside each pass; raw `sg` draws (the
   lights) slot in between layers. The offscreen main target is presented once.
5. **Offscreen targets need their own sgl context** (RGBA8); the default context matches the
   swapchain, which is BGRA8 on Metal.
6. **Shader port pattern** (`src/spike/point_lights.glsl`): one std140 block, arrays packed as
   `vec4`, fullscreen triangle from `gl_VertexIndex`. Additive blend = `SRC_ALPHA, ONE`, as raylib.
7. **Text:** fontstash's 1-channel atlas is expanded to white RGBA (alpha = coverage) and uploaded
   through a staging buffer outside any pass, so text uses sgl's stock pipeline.
8. **Readback:** sokol_gfx has none. `src/spike/native/capture_metal.m` (~40 lines) blits the
   target's `MTLTexture` into a shared buffer after `sg.commit()`. D3D11 needs the equivalent
   (staging texture + `CopyResource` + `Map`) before step 8's comparisons can run on Windows.
9. **Keycodes:** all 93 key names raylib and sokol share have identical values, and mouse buttons
   match, so saved keybinds stay valid. raylib's `KB_MENU` (348) is sokol's `MENU`; digits and grave
   differ only in name.
10. **Fullscreen differs per OS.** sokol's Windows toggle is borderless (`WS_POPUP`). On macOS it
    is native fullscreen (`toggleFullScreen`: own Space, slide animation). **Decided: keep native
    on macOS**, so no helper is needed.
11. **sokol_app owns the main loop** (init/frame/event callbacks), confirming step 3's `frame()` split.

**Windows (2026-11-17): written, compiled, not run.** `.\build.ps1 -Target spike` builds the sokol
`.lib`s with MSVC (`tools/build-sokol.ps1`, upstream sokol-odin's flags, `cl.exe` found through
`vswhere`), fetches the pinned `sokol-shdc.exe`, and links with lld. Readback is
`src/spike/capture_windows.odin`: pure Odin over `vendor:directx/d3d11` (staging texture,
`CopyResource`, `Map`). Verified from macOS only: the spike compiles for `windows_amd64` to objects
(`-build-mode:obj`), D3D11 readback and HLSL shader included. The PowerShell scripts have not
been run (no PowerShell here).

**Still open for step 1:** a run on a Windows machine (`.\build.ps1 -Target spike`, then
`bin\tormentas_spike.exe --shot out.png`), and an interactive check of resize and the fullscreen
toggle on both platforms.

**Step 2 results (2026-11-17): done.** `src/gfx/types.odin` defines `gfx.Vec2`, `gfx.Color`,
`gfx.Rect` and `gfx.WHITE/BLACK/BLANK`; every `rl.Color` (763), `rl.Rectangle` (80), `rl.Vector2` (95)
and colour constant in package main now uses them (38 files, by script). For now `Color` and `Rect`
are **aliases** of raylib's types, so the raylib calls that step 4 rewrites need no casts; step 7
makes them the only definitions. `check_boundaries.py` has a `src/gfx` rule.
Verified behaviour-neutral: tests pass, and the tools probe matches a pre-rename build within
run-to-run noise (max channel diff 9–18 both ways). The first comparison flagged a mismatch that
turned out to be the probe itself: it moves the real OS cursor, and in one run the cursor didn't
land on the gizmo (`hover=None`). Step 3's synthetic mouse input removes that flakiness.

**Step 3 results (2026-11-17): done.** `src/gfx/platform.odin` owns input, screen size and time:
`gfx.Key`, `gfx.MouseButton`, `key_pressed/down/released`, `key_pressed_any`, `char_pressed`,
`mouse_position/delta/pressed/down/released/wheel`, `screen_width/height`, `time`, `frame_time`.
348 call sites in 37 files moved by script; 7 files no longer import raylib. The main loop body is
now `app_frame()` (`main.odin`), ready to become sokol_app's frame callback.
- **Synthetic input for the tools probe.** While `gfx.set_synthetic_pointer` is on, all real
  keyboard and mouse input is ignored, in the game *and* in ImGui (devui passes the state to the
  ImGui backend). This fixed a real flake found while verifying step 2: a mouse release that
  happened during a probe run ended its scripted gizmo drag early. Three consecutive probe runs now
  differ by at most 0.25% of pixels (max channel diff 18, time-driven animation only), against up to
  9% and 235 before. The probe is now usable as step 6's reference set.
- `check_boundaries.py` now fails if package main calls raylib's input, screen-size, time or value
  types directly.
- Still to do in step 7: the event-driven key/mouse state under sokol_app. Today these procedures
  forward to raylib's polling; their signatures are already what the sokol version needs.

**Step 4 results (2026-11-17): done, and wider than planned.** Package main no longer references
raylib at all — not just drawing, but resources, shaders, window and audio:
- `src/gfx/draw.odin` (shapes, text, textures, the immediate-mode quad stream, and the
  scissor/blend/shader/camera/target modes), `resources.odin` (textures, render targets, fonts,
  images, shaders and their uniforms), `window.odin` (window, monitors, screenshot),
  `raylib_backend.odin` (the only place reaching below raylib's public API, for `rlgl`).
- **`src/snd`** is a new package for audio, since audio does not belong in a rendering package.
  raylib's audio is miniaudio underneath, so step 7's swap maps across.
- 1,125 substitutions in 36 files by script, then ~15 hand edits (the `rlgl` quad streams in
  `greybox.odin`/`shadow.odin`, the probe screenshot, and `file_exists`/`random_int` helpers that
  replace raylib's utilities).
- Signatures deliberately mirror raylib's argument order, which is what made the migration a
  rename; step 7 may tidy them once sokol is underneath.
- `check_boundaries.py` now fails if package main imports raylib or calls it directly.
- **Deviation from the plan:** raylib is spread across the `gfx` files rather than confined to
  `raylib_backend.odin`. Each file is a thin pass-through, so step 7 swaps them file by file.
- Verified: builds, tests pass, and the tools probe matches the pre-step-4 reference within the
  same margin two runs of the new build differ by (max channel diff 18–20, animation drift).
- **Left on raylib:** `ui/imgui_raylib/backend.odin`, which step 7 rewrites anyway.

**Step 5 results (2026-11-17): done.** `projection.odin` became `camera.odin` and owns the
projection *and* the camera: `cam_world_to_view[_xy]`, `cam_view_to_world_xy`,
`cam_world_to_screen[_xy]`, `cam_screen_to_world`, `cam_screen_to_view`, `cam_view_to_screen`,
`cam_dir_to_world`, `cam_begin`/`cam_end`, plus state accessors (zoom, target, offset, pan, nudge)
and `cam_init`. 147 substitutions; no `world_to_iso` or `g_camera` outside that file. P1b swaps the
isometric camera for a 3D orbit camera there without touching call sites.

**Step 6 (2026-11-17): procedure, not committed images.** The probe set is 16 MB per run and
recompresses badly (dithered lighting), so committing it would weigh on every clone forever. The
probe is deterministic since step 3 and the raylib build is in git history, so references are
regenerated instead. `tools/probe_compare.py` (standard library only, runs on Windows too) reports
differing-pixel share and max channel difference per shot.

```
git checkout <last raylib commit>      # 345692c or later, before the step 7 swap
./build.sh && bin/tormentas --tools-probe /tmp/ref
git checkout <sokol branch>
./build.sh && bin/tormentas --tools-probe /tmp/new
bin/tormentas --tools-probe /tmp/new2  # second run = the noise floor to judge against
python3 -I tools/probe_compare.py /tmp/ref /tmp/new /tmp/new2
```

Judge against the noise floor, never against zero: two runs of one build differ by well under 1% of
pixels with a max channel difference around 10-20 (clouds and flicker move with real time). Step 7
will also shift text by about a pixel (fontstash vs raylib metrics), so compare by eye as well.

**Exit:** the current game, still isometric 2D, runs on sokol with raylib gone.
**Verify:** reference-set comparison · input latency unchanged · all dev tools work (editor,
inspector, console, anim editor, lighting widget).
**Risks:** the lighting port and the pass/flip conventions. Step 1 exercises both an offscreen
pass and a shdc shader before any migration starts, and step 4 ports the simplest UI panel
end-to-end before touching the rest.

## P2 — Dedicated server and persistence (size **XL**)

**Tasks**
- [ ] **Headless binaries:** `server/world` and `server/instance`.
- [ ] **Transport swap:** Steam P2P sockets → **ENet** (`vendor:ENet`) client↔server. Keep Steam
      for identity and the store. `p2p/` becomes `net/`.
- [ ] **Backend** (in-process at first, behind an interface): SQLite, accounts, characters,
      inventories, `ItemId` minting, **character leases** (§4.2 anti-dupe invariants).
- [ ] **Server-authoritative inventory, gold and skills.** The client requests; the server decides.
      Local `save/*.bin` becomes a cache for offline dev only.
- [ ] **AoI replication:** 16×16-tile cells, per-client subscription, distance priority.
- [ ] **Quantized delta snapshots** (§4.5): ~14 bytes per entity instead of 40, 20 Hz overworld tick.
- [ ] **Load-test client:** headless fake players that walk, fight and trade. Without these you
      cannot test the scale target at all.
- [ ] Re-tune combat for 20/30 Hz; `TUNING.md` was tuned at 60.

**Exit:** 50 real clients + 500 simulated in one world, stable for an hour.
